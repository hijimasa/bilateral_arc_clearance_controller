### H1 — 独立検査が評価器のゲートの下流にあり、「接触を見落とす向き」の欠陥を原理的に検出できない

`test/omni_scenarios.cpp` の第1掃引・第2掃引。独立接触距離を計算する**前**に、評価器自身の答えで
足切りしている。

```cpp
if (eval.blocking_s >= 1e9f) { continue; }   // 被検コードが「接触なし」と言ったら抜ける
if (free_run <= 0.0f)        { continue; }
{ const float contact = independentContactDistance(...); ... }
```

第1掃引では移動8314 tickのうち **8197 tick（98.6%）が評価器自身の判定で除外**され、独立検査に
到達するのは117 tickだけである。R18 H1が「接触距離の大きさが相殺する」だったのに対し、
いまは「**接触の有無が相殺する**」。構造が一段上へ移っただけである。

実証。接触探索窓を5%短くする純粋に楽観側の変異
（`rho_max = 0.95f * fabs(w) * s_limit / max(speed, 1e-6f)`）:

```text
無変異        : 評価器の探索窓内で見落とした実接触 = 0
rho_max×0.95  : 同 = 184 tick（すべて旋回指令、最大不足 0.0654 m）→ それでも ctest 10/10
```

接触の取りこぼし側の変異は6件すべて生存する（`geo_sweep_r_min_zero`、`geo_fca_inside_removed`、
`geo_fca_drop_xrear`、`geo_trail_gate_removed`、`geo_trail_support_minus_u`、`geo_trail_rear_only`）。
より強い変異2件（`rho_max×0.9`、`tol` 負化）は**安全不変条件ではなく被覆数の閾値でしか死んでいない**
（違反0件、`independent_checks` が71や64に落ちただけ）。

**修正は検証済みである。** 独立検査をゲートの**上**へ出し、評価器と同じ窓
（`min(horizon + lead, turn_radius * eval_angle_max)`）で打ち切る:

```text
無変異                : pass、被覆は 117 / 3150 で現行と同一（コスト0）
rho_max×0.95          : 第1掃引1件・第2掃引11件の違反 → KILLED
rho_max から |w| を落とす: 第1掃引1件・第2掃引17件の違反 → KILLED
```

**窓の打ち切りは必須**で、ゲートを外すだけだと無変異でも第1掃引7件・第2掃引53件の偽陽性が出る
（`eval_angle_max = 1.05 rad` を超えた先の接触まで停止を要求してしまう）。現行の1行のゲートは、
**偽陽性を抑える役目と欠陥を隠す役目を兼ねている**。R18対応資料はこの点に触れていない。

真に独立なのは第3掃引だけで、そちらは直進指令・`heading_gain = 0` に限られる。

### H2 — 鏡映検査の `heading_gain` を0→1.5にしたことで変異killを2件失った

R14 M5 が「分布や条件を変えたときにkillを失う」と名指しした失敗形の再発である。

| 変異 | `ba544e2` | `78f6852` | 他testでのkill |
| --- | --- | --- | --- |
| `side_extent = (left_offset>=0) ? perp_left : perp_right` → `= frame.perp_left` | **KILLED** | **SURVIVED** | なし |
| governor の `support` の `along = (dx>=0)? front*dx : rear*dx` → `= front*dx` | **KILLED** | **SURVIVED** | なし |

どちらも `ba544e2` の鏡映検査が**唯一の検出器**だった。2件目は特に重い。`support` の `dx < 0` 側を
`front` に置き換える変異は、**R17 H1 が直した「進行軸方向の非対称支持」を部分的に元へ戻すもの**で
ある。R18が「対称化へ戻す変異はKILLED」と確認したのは別形（`travel_left/right` を `width/2` に置換、
および `side_gap` の左右取り違え）で、`front` 化した形だけが取りこぼされている。

原因は `cur_w` の追加ではなく `heading_gain` の引き上げである。`heading_gain` だけを0に戻し
`cur_w` の格子を残すと:

```text
heading_gain=0, cur_w格子あり : perp_left_only 18/144（worst 0.360000）、support_front 2/144
                                （worst 0.016828）→ 両方 KILLED に復帰
                                ヨー非0のセルは 87/144 で空虚性の検査も通過
heading_gain=1.5, cur_w={0}   : 両方 PASS（kill無し）
```

**R18 M3 が求めた「ヨーを空虚でなくする」は `cur_w` の追加だけで達成でき、`heading_gain` の
引き上げは目的に不要であり、その一点でkillを2件失っている。**
