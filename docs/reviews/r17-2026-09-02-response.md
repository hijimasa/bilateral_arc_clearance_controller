## 本ラウンドで変えた手順

R17は、R16対応の失敗が「測って書いた数値は全件再現し、測らずに書いた記述だけが落ちる」形をしていると
指摘した。**本ラウンドは文書に書く数値をすべてその場で測り直してから書いた。** 以下の表の数値は
いずれも `dea7662` + 本対応のコードに対する実測である。

## High

### H1 — governorの横方向スラブが対称化されていた

**修正**。`side_gap` を `|travel_lat| - travel_half` から
`travel_lat >= 0 ? travel_lat - travel_left : -travel_lat - travel_right` へ変えた。掃引箱の横区間は
`[-travel_right, travel_left]` であり、進行軸まわりに対称ではない。

指摘のとおり、この非対称性は本packageが既に知っていた性質である
（`src/arc_trajectory_evaluator.cpp` の `perp_left` / `perp_right`）。governorだけが単一値を使っていた。

**検証**。**非対称footprint（front 0.70 / rear -0.30）での鏡映不変性検査**を追加した。既存の4方位
対称性検査は正方footprintを使うため、この欠陥を原理的に検出できない。追加した検査は修正前に
`worst 0.080000 m/s` で落ち、修正後に通る。対称化へ戻す変異、および `travel_right` を `travel_left`
と同一にする変異はいずれもKILLEDされる。

### H2 — deadband再判定が恒久停止を作る

**修正**。**deadbandを適用しない**ようにした。deadbandはジッタ抑制の量子化であって許容性より優先される
ものではない。

指摘の機構を計装で厳密に再現した。同梱suiteで発火する**14件はすべてヨーのみのゼロ化**であり、
**14件すべてで判定前の指令は既にstoppableだった**。

```text
DBBRAKE speed=0.1806 pre=(0.0470,0.0098,0.1744) post=(0.0470,0.0000,0.1744) pre_ok=1
DBBRAKE speed=0.2185 pre=(0.1692,0.0082,-0.1382) post=(0.1692,0.0000,-0.1382) pre_ok=1
total: 14   of which pre-deadband was stoppable: 14
```

**中間案として「停止可能な速度まで落とす」を試し、実測して捨てた**。deadband後の弧は
`safe_speed_for(finalized) = 0`、すなわち安全速度が存在しない（`free_run <= 0`）ため、減速では救済でき
ない。14件中7件が完全停止のままだった。

**代償を測った**。R17 H2は「違反数しか測っておらずコストを一度も測っていない」ことを欠陥とした。
本対応では両方を測る。

| | 修正前 | 修正後 |
|---|---|---|
| deadband由来の完全停止（同梱suite）| **14件** | **0件** |
| 安全不変条件の違反（両掃引）| 0件 | 0件 |

**閉じられなかった点を明記する**。この修正に判別する回帰は用意できなかった。14件はいずれも一過性で
軌跡に現れず（廊下シナリオの `stop_ticks` と最終xは修正前後で同一）、指摘が用いたrigの恒久停止数
（113/220など）は当方の分布では再現しない（3 seedとも0/220）。「完全停止へ戻す」変異は生存する。
捏造せずここに記録する。

### H3 — 第1掃引のSTOP不変条件が一度も評価されない

**修正**。加算文が第2掃引にしか入っていなかった。第1掃引にも入れた。原因は、2つの掃引で字下げが
異なるため一括置換が片方にしか当たらなかったことである。

**検証**。`Status::STOP` が `vy` を見ない状態へ戻す変異で、**第1掃引が29件、第2掃引が101件**を検出する
（修正前は第2掃引の101件だけだった）。

### H4 — 廊下の進入オフセット境界が実測と食い違う

**修正**。0.30〜0.50 mを0.002 m刻みで掃引し直した（101セル。接触・非完走・通路外への迂回のいずれかを
不合格とする）。

| 通路幅 / 壁厚 | 不合格セル数 | 最初に不合格になるオフセット |
|---|---|---|
| 1.2 m / 0.10 m | **0 / 101** | なし |
| 1.1 m / 0.10 m | 35 / 101 | **0.418 m** |
| 1.2 m / 厚みゼロ | 10 / 101 | **0.476 m** |
| 1.1 m / 厚みゼロ | 46 / 101 | **0.372 m** |

R16のH2・H3修正で挙動が改善しており、旧記載（「0.45 mで入口停止」「1.1 mは0.36 mから迂回」）は
いずれも古い。日英文書と試験コメントを上表へ合わせた。

### H5 — 「`bac_filter_node` は全方向指令を通さない」が偽

**修正**。実測に合わせた。正しくは「**部分的にしか通さない**」であり、前進成分があるときは横速度が
残る。

```text
cmd_vel_in(linear.x=0.30, linear.y=0.30) -> cmd_vel_out(linear.x=0.234, linear.y=0.187)
cmd_vel_in(linear.x=0.00, linear.y=0.30) -> 出力 0
```

日英文書と、同じ偽の主張を書いていた `docker/nav2-jazzy/test_package.sh` のコメントを直した。gateの
コメントは「設定の受理・拒否だけを検査しており、出力経路については何も言わない」という、実際に
検査している範囲まで狭めた。
