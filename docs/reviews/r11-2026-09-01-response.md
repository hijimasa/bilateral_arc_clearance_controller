## H1 — 却下された設定の半適用

**修正**。検証を副作用の**前**に行うようにした。`bac::detail::validateMotionModelParams(const Params &)`
を新設し、`makeMotionModel` はこれを呼んでから構築する。`BacCore::setParams` は先頭でこれを呼ぶため、
不正設定では `params_` も `motion_model_` も一切変更されない。

```cpp
void BacCore::setParams(const Params &params)
{
  detail::validateMotionModelParams(params);  // ここでthrowすれば以降は実行されない
  ...
  params_ = params;
  rebuildMotionModel();
}
```

併せて `AckermannMotionModel` のコンストラクタにも同じ検査を置いた（多重防御）。factoryを経由しない
直接構築でも、曲率上限が負または無限大のmodelは生成できない。

**検証**。再現コードの出力が修正後に次へ変わることを確認した。

```text
setParams threw: bac: Ackermann turn_radius_min must be positive
after rejected setParams  limitReachableCommand((0.3,0),(0.3,0)) = (0.3000, 0.0000)
params().turn_radius_min = 1.00
```

回帰テストを `bac_ackermann_motion_model_unit` へ追加した。却下後に (a) 従前のパラメータが残ること、
(b) 直進指令が直進のまま返ること、(c) 旋回円の制約が生きたままであることを検査する。**H1の修正を
一時的に戻すと当該テストが落ちること**を確認済みである。

## M1 — 文書と実装の乖離

**修正**。指摘の5件をすべて訂正した。

1. 「差動二輪は曲率を制約しない」→ 「差動二輪は並進候補のみを scoring 上の下限 `turn_radius_min` で
   縛り、その場旋回は自由」へ（日英）。
2. Ackermannのsample範囲を
   `|kappa| <= min(1 / turn_radius_min, limits.w_max / |linear.x|)` へ訂正し、`limits.w_max` が候補曲率の
   格子自体を狭める条件（`|v| > w_max * turn_radius_min`）と、後退速度も同じ範囲で扱われることを明記した
   （`parameters.md` と `algorithm.md` の日英4ファイル）。
3. 後方goal試験の参照設定を「`turn_radius_min` 以外を揃えた差動二輪」へ訂正した。
4. `velocity_min` 行にAckermannでは指令全体が0になることを追記した。
5. 日本語版の「前進候補」を「並進候補（前進・後退とも）」へ訂正した。同種の誤りが
   `bac_core.hpp` の `turn_radius_min` のコメントにもあったため、モデル別の意味と併せて書き直した。

軽微な指摘のうち、「必ず車両が追従可能」→「幾何的には追従可能」、英語版チェックリストから
Nav2 recovery確認が欠落、READMEのAckermann coverage記述に単体検査が含まれていない点も併せて修正した。

`setSpeedLimit` が未文書という指摘は、Ackermann対応とは独立した既存範囲のため今回は対応していない。

## M2 — 空振りしていたテスト

**修正**。ミューテーション9件すべてについて、これを殺すアサーションを追加した。

| ミューテーション | 修正後 | 殺したアサーション |
|---|---|---|
| `commandChange` をヨーレート差へ | KILLED | 同一曲率・異速度で変化0、同一ヨーレート・異速度で変化>0 |
| probe を固定値へ | KILLED | 低速時のprobeが旋回円へclipされる |
| deadband を差動二輪型へ | KILLED | `velocity_min` 未満で指令全体が0になる |
| sampler が速度capを無視 | KILLED | capを下げると格子も下がる／障害物迂回シナリオ |
| validator が常にtrue | KILLED | 最小半径より鋭い弧（前進・後退とも）を拒否する |
| refinement のclipping除去 | KILLED | 上限中心のrefinementが旋回円を出ない |
| 直進候補を曲げる | KILLED | 偶数 `w_samples` でも各速度行に真の直進弧がある |
| `setParams` がmodel切替を無視 | KILLED | `turn_radius_min` 据え置きでもmodelが切り替わる |
| goal進捗ゲート除去 | KILLED | 前進のみAckermannがその場に留まる（走行距離・最終位置・停止） |

`testRearGoal` の合格条件は「goalに近づかない」ではなく「その場に留まる」へ置き換えた。閉ループ計測に
走行距離 `travelled_distance` と操舵の滑らかさ `max_curvature_step` を追加した。ゲート除去
ミューテーションでの失敗メッセージは `travelled 3.998219 m` であり、指摘どおりの逆走を捉えている。

空振りアサーションへの対応:

1. hysteresis の検査は、曲率差とヨーレート差が一致しない**異なる速度間**の比較へ置き換えた。
2. `A(f(A))` 形の検査はそのまま残し、独立した**否定側**の検査（最小半径より鋭い弧を拒否する、後退でも
   `|v|` で判定する）を追加した。
3. `!violated_turning_radius` と重複していた検査を、独立した事実（半径の小さい車両は、半径の大きい
   車両には許されない曲率を実際に使う）の検査へ置き換えた。
4. `ros_adapter_unit.cpp` の到達不能な旋回半径検査は**削除**した。当該fixtureは車両が停止状態で選択弧が
   常に直進のため、旋回を成立させられない。走行速度と横偏差経路の付与を試したが成立せず、
   「テストに見えて何も検査していないコード」を残すより削除する方が正しいと判断した。代わりに、当該tick
   でAckermannが `(0, 0)` へ制動することを積極的に検査するアサーションを置き、旋回半径の拘束が
   単体テストとシナリオ側でカバーされている旨をコメントに明記した。なお、同一tickを `diff_drive` 設定で
   実行すると `(0.0, -0.125)` になるため、「その場旋回を出さない」検査はパラメータがcoreへ到達している
   ことの証拠として機能している。

## L1 — 差動二輪の挙動変化

**文書化のみ**。指摘のとおり新しい挙動の方が正しく（旧実装は admissibility 未検査のその場旋回を出して
いた）、17シナリオ harness の出力は byte-identical である。`avoid_status` の購読者が観測しうる変化
であるため、CHANGELOG に `AVOIDING` → `STOP` の変化として記録した。

旋回不許可時に `out_w` を1 tickで0へ落とす点は `acc_w` 契約の逸脱だが、これは本blockの直後にある制動
fallback（`limitReachableCommand(current, {0,0})` の結果を、旋回不許可なら0で上書きする）と同じ方針で
あり、**「障害物へ向かう旋回を継続すると約束しない」という意図的な安全側の逸脱**である。挙動は変更して
いない。

## L2 — 閾値の不整合

**修正**。`sampleCandidates` の後退escape行で、半速度行 `v_rev / 2` にも停止判定閾値の再確認を入れた。
これによりsamplerは自身のvalidatorが拒否する候補を生成しなくなる。差動二輪側は挙動を変えないため
触れていない。

## L3 — `bound == 0` での重複候補

**修正**。`refinementCandidates` の先頭で `bound > 0` を確認し、満たさない場合は空を返すようにした。

## L4 — `weights.hysteresis` の単位差

**修正**。`docs/parameters.md` と `docs/en/parameters.md` の重み節に、単位がモデルで異なること、
Ackermann側が `2 / turn_radius_min`・差動二輪側が `2 * w_max` に比例すること、同梱設定例では偶然一致
するが `turn_radius_min` を小さくすると `weights.clearance` を圧倒しうることを追記した。

## L5 — Ackermannシナリオの薄さ

**未対応。次cycleへ残す**。`safety_stop` と狭路系の世界をAckermann側へ移植していない。今回追加した
`travelled_distance` / `max_curvature_step` は計測のみで、狭路での操舵振動に対する閾値検査はまだ無い。
速度capのミューテーションは単体テストで殺せるようになったが、閉ループでの独立した確認は
障害物迂回シナリオの副次的な失敗に依存している。
