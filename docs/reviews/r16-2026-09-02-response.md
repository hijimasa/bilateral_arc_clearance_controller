# 第16回リリースレビューへの対応

レビューID: `R16`
対象レビュー: [r16-2026-09-02-findings.md](r16-2026-09-02-findings.md)（2026-09-02、`a9c6c31` 時点。
判定 **Hold**、High 5件・Medium 13件・Low 10件）
対応日: 2026-09-02
対象package: `a9c6c31` に対する対応。本対応は `c74fe7d`（H2・H4・H5）、`68a8ed9`（H3）、`4739c6f`
（H1と文書）の3commitである。R16の記録commitは `3708fd4` である。
対象benchmark: 該当なし

High 5件すべてと、統合前条件とされたMedium（M7・M8・M9・M10）、および修正の過程で解消したMedium
（M1の一部・M13）に対応した。残るMediumとLow全件は次cycleへ送る。

**本ラウンドは検査を先に書き、対象コードに対して落ちることを確認してから修正した。** R16が指摘した
「格子点で測って全域を主張した」「killを失ったことに気付かずKILLEDと書いた」はいずれも、修正を先に
書いて後から検査を合わせたことに起因する。順序を変えた。

## High

### H5 — `withLinearSpeed` の方向復元に検査が無い

**修正**。差動二輪とAckermannの単体試験に、後退指令が後退のまま曲率を保って減速されることを検査する
項目を追加した。R16が挙げた「常に前進へ解決する」変異は両モデルでKILLEDになる。全方向モデルの縮退
（進行方向が無い指令の減速）が `{0,0,0}` を返すことも検査した（R16 L-A6）。

### H4 — R15対応が新設したコードが試験から一度も実行されない

**修正**。原因はR16の診断どおりで、`testEmittedCommandCanAlwaysStop` が
`acc_v = acc_w = 1000` として `limitReachableCommand` をno-opにしているため、出力段にもfallbackにも
構造的に到達できないことであった。**加速度上限が実際に拘束する第2の掃引**
（`testEmittedCommandCanStopWhenAccelerationBinds`、40000試行）を追加した。

計装で確認した到達回数:

```text
追加前: fallback=0  rung1=0  rung2=0
追加後: fallback=318  rung1=318  rung2=67
```

`stoppable` を常にtrueにする変異、fallbackのゲートを外す変異とも**KILLED**（ゲートを外すと違反32件）。

### H2 — deadbandが判定の後に走り、publishされるtwistで不変条件が破れる

**修正**。deadbandが指令を変えた場合に限り、publishする指令を `stoppable` で再判定し、通らなければ
制動する。非ホロノミック指令は影響を受けない（直線指令のdeadband以下のヨーを0にしても弧は変わらない）。

**この欠陥は理論上のものではなかった**。H4で追加した拘束加速度下の掃引で、修正前は**7件**の
publish済み指令が接触前に停止できず、その**すべてが、弧の判定後にヨーを0にされた斜行指令**であった。
修正後は0件である。

### H3 — 速度governorが前進軸のままで、横移動が同じ壁へ32%速く突っ込む

**修正**。governorのslab判定を進行方向フレームへ一般化した。点の縦・横座標、車体の前方への広がり、
後縁のいずれも進行方向の支持関数である。`vy = 0` で従来式と恒等であり、差動二輪とAckermannの出力は
バイト同一である。

**検査は閾値ではなく対称性**である。正方footprintと等方marginの下では、壁へ前進する問題と、同じ壁を
90°回して横移動する問題は同一である。4方位すべてが同じように減速されることを検査する。

**被覆は部分的であり、そう記す**。一般化の4要素のうち、この検査が殺すのは横方向gapのみである。縦座標・
前方への広がり・後縁の3つは、検査した幾何が横方向の枝で決まるため生存する。届かせるための幾何を
捏造せず、記録に留める。

### H1 — 廊下進入時の接触

**H2とH3の修正で解消した。専用の変更は入れていない。** R16が用いたのと同じ0.002 m刻み61セルの掃引を
現在のコードで再実行した結果、**接触0・非完走0**である（`616746b` では2セル接触・3セル非完走）。

**あわせて、この指摘の性質について記録する。** R16 H1の接触は、試験worldの壁が厚みゼロの線分で
あることに依存していた。ビーム数を上げると消える。

| ビーム数 | 61セル掃引 |
|---|---|
| 720（0.5°）| `616746b`: 2セル接触・3セル非完走 |
| 2880 | 接触0・全完走 |
| 7200 | 接触0・全完走 |

接触直前の点群を数えると、壁の端点はほぼ見えていない（前方0.9 m以内の点が0〜1個で、footprint内に
最初の点が現れるのは既に車体内部）。厚みゼロの面をほぼ接線方向から見ると、ビーム間隔より薄い見かけの
断面はレイの隙間をすり抜ける。**測れないものは避けられない。**

したがって対応は2つに分けた。

1. **試験worldを現実に合わせた**。`bac_sim::World::addCorridorXWalls` を追加し、通路を厚みのある箱で
   構成する。廊下centeringのシナリオは0.10 mの壁を使う。実測では厚み0.05 / 0.10 / 0.20 mのいずれでも
   全61セルが正常である。
2. **手法の制約として文書化した**。`docs/algorithm.md`（日英）の「BACが保証しないもの」に、薄い壁へ
   ほぼ平行に進入する場合、角度分解能によっては触れようとしている縁が点として現れないことを記載した。

厚みゼロの線分に沿って進入する構成は評価上の縮退であり、シナリオとして妥当ではない。これは指摘者では
なく**この試験worldを書いた側の誤り**である。

## Medium（対応したもの）

### M1（一部）— 出力段の生存変異

H2・H4の検査により、R16が挙げた5変異のうち `travel_margin(out_command())` を前方余裕へ戻す変異と、
停止判定を `fabs(out_v)` へ戻す変異が**KILLED**になった。接触判定horizon（M2）と `T5` は生存したまま
であり、次cycleへ送る。

### M7 — 試験コメント内の記録帯

**修正**。3件を実測へ揃えた。

- `testGoalOrientationIsHeld`: 0.009–0.102 / 0.959–1.741 → **0.0065–0.0603 / 0.5406–2.9426**、および
  測定条件（`heading_gain` 1.5）。壊れた挿入「0.541 rad,」も除いた。
- `testLateralRowIsContactChecked`: 「abeam 0.50–0.95の全点で0.1800」は誤りで、変異は0.50–0.65で生存
  する。主張をこのシナリオが実際に走らせる0.70 mに限定した。
- `testNarrowCorridorCentering`: 厚い壁のfixtureで再測定し、omni **0.0126–0.0151** / diff
  **0.0291–0.0361** とした。

### M8 — R15対応資料のH4表の誤り

**訂正をここに記録する**。規約3に従いR15の文書は書き換えない。同資料のH4表は

> 1.2 m通路 / 進入オフセット0.45 → 完走 0.0127

とするが、実測は **final x = 1.5440 で入口停止**である。同一commitの試験コメントと
`docs/algorithm.md`（日英）は正しく「0.45では入口で停止」と書いており、当該表のみが誤っていた。

### M9 — 差動二輪参照シナリオ数

**修正**。日英の履歴文書を5→**4**へ訂正した（`diffDriveReferenceParams()` の使用は4箇所）。R15 M13の
訂正が3→5と行き過ぎていた。

### M10 — `bac_filter_node` が全方向指令を通さないことが未文書

**修正（文書とgateの主張のみ）**。nodeそのものは評価用であり、Nav2 plugin側が `vy` を正しく入出力
するため、実装の先送りは維持する。次の2点を直した。

- `docs/nav2_integration.md`（日英）に、nodeは `motion_model.type: omni` を受理するが上流の
  `linear.y` は出力に現れないことを明記した。
- `docker/nav2-jazzy/test_package.sh` のomni実ノード検査に、これが検査しているのは設定の受理・拒否で
  あって全方向の出力経路ではないこと、その経路はlabel付きctestが見ていることをコメントした。

### M13 — governor capの記述

**修正**。「capはベクトルに掛かる」は無条件には成立しない。横軸に掛かることは事実だが、ノルム上限は
`|limits.v_min|` まで緩む（後退候補がgovernorで消えないようにするためで、差動二輪と同じ扱い。既定の
`v_min` は-0.1）。日英とも条件つきの記述へ改めた。

## 閉じられなかったもの（正直な記録）

- **H3の一般化のうち3要素**（縦座標・前方への広がり・後縁）に判別する検査が無い。検査した幾何が
  横方向の枝で決まるためで、届かせる幾何を捏造していない。
- **R16 M2**（候補段の接触判定horizon）は生存したままである。`min_eval_distance = 1.6` の床が支配する。
- **R16 M3**（`stoppable` の三段ladderの第3段が到達不能）は記述の問題として残す。第2段は
  `Twist2D(0, w, 0).speed() == 0` により常にtrueで、第3段には到達しない。挙動上の悪化は観測されない。
- **R16 M4**（純横移動中に `Status::STOP` を報告する）、**M5**（property testの非空虚guardが被覆と
  逆相関する）、**M6**（`acc = 1000` が出力段を不活性化する。第2の掃引で補ったが第1の掃引の性質は
  変わらない）、**M11**（廊下centering表の1.3 mセルと測定条件の不足）、**M12**（`wrapAngle` の修正に
  検査が無い）は次cycleへ送る。
