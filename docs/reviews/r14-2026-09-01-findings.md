## 対象と方法

本レビューは、これまでの13回と異なり **`feature/ackermann-motion-model` を `main` へ統合してよいか** を
判断するために行った。したがって焦点は2つある。

1. **既存の差動二輪利用者への影響**。`2939c1b` は `src/bac_core.cpp` を595行書き換える再構成であり、
   Ackermannを使わない利用者もこの変更を受け取る。挙動が保存されているかを、対応資料ではなく
   `main` の実装との数値比較で確かめる。
2. **レビューを一度も受けていない `112eb35`**。R13対応commitであり、その主張はR13が
   `3bd88cb` に対して行ったのと同じ方法で独立に再検証する。

3名のレビューアが独立に担当した。A: 幾何・アルゴリズム中核と `main` との挙動差分。B: 検証装置自体と
`112eb35` の主張の再検証。C: Nav2結合・設定・パッケージング・日英文書・コンテナ検証。

検証手段: plain CMake Release `ctest` 7/7、Debug + ASan/UBSan（`detect_leaks=1`）7/7、
ROS 2 Jazzy / Nav2コンテナ 8/8、`main` と `112eb35` の状態同期per-tick差分20万tick、
harnessに存在しない10世界での閉ループ比較、production codeのミューテーション計29件超、
yaml摂動26件、点順序不変性・鏡像対称性のメタモルフィック試験各12万tick、非有限入力42ケース、
Ackermann不変条件の再確認36万tick。

## 結論

**main統合は可能である。** 統合判断の中心である「既存の差動二輪利用者が壊れるか」への答えは、実務上
「壊れない」である。抽出された弧幾何（`firstContactArcLength`、`evaluateArcWindows`）は式が1つも
変わらない逐語移設であり、17本のシナリオharnessは出力md5まで一致する
（`c50d9b826a69ad56931925a63890e752`）。harnessに無い10世界の閉ループでも9世界が軌跡bit-identicalで、
残る1世界の最大偏差は2 mmである。`motion_model.type` の既定値は `diff_drive` で、パラメータ不在時も
`diff_drive` に解決し、誤記は `std::invalid_argument` でfail-closedする。`validateMotionModelParams` は
`DIFF_DRIVE` を素通しするため、既存設定が新たに起動失敗することもない。Critical / Highの機能欠陥は
1件も無い。

無条件Goを妨げるのは、R13と同じく **packageが自身について提示するevidenceの欠陥** である。ただし
R13との違いが1点ある。R13は「evidenceの欠陥」を4件指摘し、`112eb35` はそのすべてに実体のある修正を
入れた。にもかかわらず本ラウンドは、**その修正自身が持ち込んだ欠陥を5件検出した**（H1、M3、M4、M5、
M6）。閾値をtripwireでなくすための修正が新しいtripwireを作り、ガードをファイルに紐付ける修正が
キー集合に紐付き、アサーション集合を揃える修正が到達不能なアサーションを1件足している。これは
個々の修正の質の問題ではなく、**修正の効果を測る基準が修正のたびに再導出されていない** ことの帰結で
あり、次ラウンドで同じ形が再発しやすい。

## Medium

### M1 — 差動二輪の出力段に測定可能な挙動変化があり、その新しい意味論を固定する検査が1本も無い

`src/bac_core.cpp` の出力reachabilityループ（`2939c1b` / `8fd0d7e` で新設）。**main統合の観点で最も
重要な指摘である。**

`main` は「wをclamp → 変化したら弧を再評価 → wを据え置いてvを `v_safe` へ、反復なし」。`112eb35` は
「最大8回反復し、`withLinearSpeed` で曲率保存減速 → 再clamp → 再評価。収束しなければ `out_v = 0`、
`out_w = rotation_admissible ? braking.w : 0`」。

同梱 `diff_drive` 設定で、毎tick coreを作り直して内部状態を一致させたper-tick差分20万tick:

```text
diffs = 1014 (0.5070%)
  A 旧spin      -> 新stop                 977   (R11 L1で既報)
  C 旧translate -> 新stop                   5
  E 新 v=0 + 残留yaw、旧はtranslate         17
  G 同wで新vが小さい                        12
  H 同vでw相違                               3
例: cur=(0.084, 1.135)  new=(0.0359, 1.0101)  old=(0.2362, 1.0101)   # 新は6.6倍遅い
```

観測されたすべてのクラスで新実装が保守側（停止・減速・旋回放棄）である。R11はこの残差を「8 tickの
意図した曲率保存減速」と特徴づけたが、実測ではA以外の残差が20万tick中37 tick・**4クラス**あり、うち
E（17 tick）は旧実装が一度も出さない純粋なその場旋回 `(0, w)` である。

問題は変化そのものではなく、**新しい意味論を守る検査が存在しない**ことである。以下3件のミューテーション
がいずれも7/7を通過する。

- `c01` 曲率保存減速を `main` 相当へ戻す → **SURVIVED**
- `c02` `!output_admissible` fallbackの `rotation_admissible` ガード削除 → **SURVIVED**
- `c03` `kReachabilityIterations` 8 → 1 → **SURVIVED**（差分は1014→1051、Eクラス17→66でループ自体は
  実効的に効いている）

現実的な閉ループでは事実上再現しない（10世界中9世界がbit-identical、残り1世界が2 mm）ため統合を
阻害しないが、誰も守っていない挙動変化は次のrefactorで無言で戻りうる。`c01` / `c02` / `c03` の
いずれかを殺す回帰を1本置くか、既存差動二輪利用者向けの挙動変化としてCHANGELOG / リリースノートに
明記することを統合の条件とする。

### M2 — Ackermann曲率上限の `limits.w_max` 項が全fixtureと同梱設定で構造的に不活性であり、導入以来一度も検査されていない

`src/ackermann_motion_model.cpp::yawRateBound` / `curvatureBound`、`src/motion_model.cpp`。

曲率上限は `min(w_max, |v| / turn_radius_min)` だが、すべてのAckermann設定で
`v_max <= w_max * turn_radius_min` が成り立ち、`min` は常に半径項を選ぶ。各設定4万tickで
`|v| / R > w_max` となったtickを計数した。

| 設定 | R | w_max | v_max | binding tick | max\|w\| |
|---|---|---|---|---|---|
| shipped yaml | 1.00 | 0.80 | 0.50 | 0 | 0.5000 |
| ackermann_scenarios | 1.00 | 1.00 | 0.40 | 0 | 0.4000 |
| ackermann_motion_model_unit | 1.20 | 1.00 | 0.50 | 0 | 0.4167 |
| （新規）| 0.50 | 0.40 | 1.20 | 23 503 | 0.4000 |
| （新規、極端）| 0.20 | 0.15 | 1.50 | 22 073 | 0.1500 |

結果として、以下3件のミューテーションがすべて7/7を通過する。

```text
S1 yawRateBound から min(w_max, ...) の w_max 項を削除              SURVIVES
S2 validateMotionModelParams の w_max 検査を削除（R12 L1のガード）   SURVIVES
S3 コンストラクタの検査を削除（= R13 L6の修正そのものをrevert）      SURVIVES
```

`w_max` は `test/ackermann_motion_model_unit.cpp` に **0回** しか現れない。R12 L1とR13 L6は2ラウンド
かけてこの項の**値の検証**（正値・有限性）を整備したが、その項が**上限として機能すること**は誰も
確かめていない。文書（R11 M1訂正2）が明示する「`|v| > w_max * turn_radius_min` の速度域では `w_max` が
候補曲率の格子を狭める」挙動は、一度も実行されていない。

コード自体は正しい。bindingさせれば上限は厳密に効き（`max|w|` が `w_max` に一致、半径違反0、spin 0）、
検証だけが届いていない。`v_max > w_max * turn_radius_min` となる設定を1つfixtureへ追加し
`|w| <= limits.w_max` をアサートすれば `S1` は死ぬ。

### M4 — `curvature_sign_changes <= 22` は破壊側を掃引すると帯が重なり、指標自体がhorizon依存の累積カウントである

`test/ackermann_scenarios.cpp` の `testSafetyStopReverseEscape`。

R13 M2対応は正常側を `v_max` 0.30–0.60 × plant `curvature_rate` 0.7–2.0で掃引し（再測でも最大**17**で

当該シナリオの条件（8 s、`v_max = 0.4`）では8対25で分離しており対象ミューテーションは実際に死ぬため、
統合は阻害しない。閾値を残すなら測定した帯の**両側**を掃引した上でコメントに明記すべきである。

## main統合についての判断

**統合してよい。** ただし本レビューのHigh 1件とMedium 9件は、統合の前後どちらで直すかを明示して
決めること。

統合を阻害しない根拠は上記「main統合の可否に直接答える項目」に尽きる。既存の差動二輪利用者に対する
影響は、`main` との数値比較で 0.507%/tick の出力段差分（すべて保守側）と、閉ループ10世界中9世界の
bit-identical、残り1世界2 mmに限定される。後方互換性はパラメータ既定値とfail-closedな検証で担保され、
唯一の意図的な挙動変更はCHANGELOGに記載済みである。

統合前に済ませることを推奨する項目（いずれも小さい）:

1. **M1** — 出力段の新しい意味論を、回帰1本かCHANGELOG / リリースノートの明記のいずれかで固定する。
   既存利用者が受け取る唯一の実挙動変化であり、統合後に発見されると原因の切り分けが難しい。
2. **M7 / M8** — 文書が実装について述べている虚偽2件。統合すると `main` の文書が誤った状態になる。
