## 対象と方法

3名のレビューアが独立に担当した。判定はA **Hold**、B **Conditional Go**、C **Hold**。

検証手段: plain CMake Release `ctest` 10/10、Debug + ASan/UBSan 10/10、ROS 2 Jazzy / Nav2コンテナ
11/11、production変異 計81件超、yaml摂動31件、seed掃引10種、廊下の進入オフセット掃引 計664セル
（幅・壁厚を変えた4条件×61セルおよび201セル）、乱択閉ループ延べ約570万tick、鏡映不変性検査、
`main` との差分probe（3モデル×約3万tick、および5 seed×16000行）、計装ビルドによる分岐到達回数。

## 結論

**統合してはならない。**

製品コードの安全性そのものは収束している。約570万tickの閉ループで**車体接触は0**、安全不変条件の
破れは浮動小数の丸め1件のみ（差1.3e-4）である。R16のHigh 5件はいずれも実体を伴って修正されており、
R16 H1（廊下進入時の接触）は独立に再現して解消を確認した（壁厚0 / 0.05 / 0.10 / 0.20 mの4条件×61セル、
さらに201セルで接触0・非完走0）。R16対応がKILLEDと申告した12変異は全件再現し、生存と正直に記した
4件も申告どおりであった。差動二輪とAckermannへの回帰は無い。

Holdの理由は2系統ある。

1. **R16対応commitが2件のコード回帰を持ち込んだ**（H1・H2）。いずれも同梱suiteでは検出されない。
   H1は「H3の一般化が横方向について支持関数になっていない」という、**修正そのものの誤り**であり、
   同梱設定が対称footprintであるために検査が素通りする。H2は「不変条件の違反を0にしたが、その代償を
   一度も測っていない」もので、恒久停止が26〜45%増えている。
2. **R16対応commitが3件の再現しない主張を持ち込んだ**（H3・H4・H5）。うちH3は検査自体の空虚化で
   ある。

R11以降このプロジェクトが繰り返し検出してきた「packageが自身について提示するevidenceの欠陥」は、
**4ラウンド連続で、同じ作成者の対応文書に**現れている。R17で新たに分かったのは、その内訳が
「測って書いた数値は全件再現し、測らずに書いた記述だけが落ちる」という形をしていることである。
R16対応が実際に再測定した数値（`heading_gain` 表10セル、goal姿勢の帯、廊下centeringの帯、61セル掃引、
md5）は3名の独立再測で**すべて完全に一致した**。

## High

### H1 — governorの横方向スラブが進行方向の支持関数になっておらず、鏡映不変性が壊れた

`src/bac_core.cpp::evaluateProximity` の `travel_half` と `side_gap`。**`68a8ed9`（R16 H3対応）が
持ち込んだ回帰である。**

`side_gap = |travel_lat| - support(n)` は掃引箱の横区間を進行軸まわりに**対称化**している。真の区間は
`[-support(-n), support(n)]` であり、差は `(front + rear) * uy` である。footprint箱は `y = 0` 対称で
marginも等方なので、問題全体は `y → -y, vy → -vy, w → -w` で厳密に不変でなければならないが、実装は
これを破る。

```text
footprint front=0.50 rear=-0.50 : mirror breaks   0 / 4000
footprint front=0.35 rear=-0.35 : mirror breaks   0 / 4000   ← 同梱omni yaml
footprint front=0.70 rear=-0.30 : mirror breaks 186 / 4000  worst=0.349554
   worst: current(v=0.3096 vy=-0.2680) out v=0.0000 / 鏡像 out v=0.3496
a9c6c31 では同じ4条件すべて breaks 0 / 4000
```

左crabでは真に衝突コース上の点が最大 `|front + rear|` = 0.40 m幅で正面枝から漏れ、右crabでは同じ幅
だけ過剰にcapする。**R16 H3が直そうとした過小減速が、非対称footprintでは片側に残っている。**

R16対応資料の「点の縦・横座標、前方への広がり、後縁のいずれも進行方向の支持関数である」は、横座標に
ついて偽である。正しい非対称スラブへ直す変異は `ctest` 10/10を通過して**生存する**。同梱設定が対称
footprintであるため、追加された4方位の対称性検査はこの欠陥を原理的に検出できない。

なお、この非対称性は本packageが既に知っていた性質である。`src/arc_trajectory_evaluator.cpp` は
`perp_left` と `perp_right` を左右別に計算している。governorだけが単一の `travel_half` を使う。

### H2 — deadband再判定の救済策が恒久停止（吸収状態）を作る

`src/bac_core.cpp::BacCore::process` のdeadband再判定。**`c74fe7d`（R16 H2対応）が持ち込んだ回帰で
ある。**

発火時の出力は `limitReachableCommand` を通さない生の `(0, 0, 0)` である。計装で採取した**13462件の
brakeイベントは全件がヨーのみのゼロ化**であり、**全件でdeadband前の指令はstoppableだった**。発生速度は
0.022〜0.178 m/sのcreep域である。原因は `min_eval_distance = 1.6 m` の距離床で、0.0218 m/sでは73秒ぶんを
外挿することになり、ヨー差0.52 radを生む。静止すると入力が変わらないため同じ判定を繰り返す。

```text
同梱deadband既定値, holonomic, 220試行 × 1200 tick
seed 20260902 恒久停止 113 / 82 (+38%)   seed 7 123 / 85 (+45%)   seed 424242 115 / 91 (+26%)
head-only deadlocks 30 のうち 24 で再判定が発火
  trial 25: head stalled 733 ticks (db_brake=733) final x=6.52 | a9c6c31 stalled 0 final x=10.66
commit帰属: prev 91 → c74fe7d 114 → head 115
```

R16対応資料は「修正後は0件」（違反数）しか測っておらず、**コストを一切測っていない**。R16 H1が恒久
停止を除去対象とした基準をそのまま適用する。

### H3 — `testEmittedCommandCanAlwaysStop` のSTOP不変条件が一度も評価されない

`test/omni_scenarios.cpp` の第1掃引。`stop_while_moving` は宣言とassertionだけがあり、**増やす文が
関数本体に存在しない**（`result.status` を読む箇所が無い）。計測でも第1掃引は常に0で、
`Status::STOP` 変異を当てても10 seedすべてで0のまま、落ちるのは第2掃引だけである。失敗しても
`"...(0; first: )"` と空のwitnessを印字する。

R16対応資料の「両方の乱択掃引に不変条件として組み込んだ」は偽であり、「修正前は101 tick」は第2掃引
のみの数である。R14 M6以来このプロジェクトが繰り返し指摘してきた「検査していないのに検査している
ように読めるassertion」を、それを直す作業で作っている。1行の追加で解消する。

### H4 — 廊下の進入オフセット境界が実測と食い違い、R16の統合前条件が未了である

`docs/algorithm.md`（日英）と `test/omni_scenarios.cpp` のコメント。記載は「1.2 m通路では0.30〜0.40 mで
通過するが0.45 mでは入口で停止し、1.1 m通路では0.36 m以上で外側を迂回する」。

```text
厚み0.10 gap1.20: off=0.450 final=(10.2118,0.0091) collided=0   ← 完走
厚み0.00 gap1.20: off=0.450 final=(10.2091,0.0051) collided=0   ← 完走
厚み0.10 gap1.10: 0.36-0.50 で非完走は 0.448 と 0.466 の2セルのみ
```

R16のH2・H3修正で挙動が改善したのに再測定していない。BとCが独立に同じ結論に達した。R16の統合前条件は
「実測に合わせる」ことを求めており、このまま統合すると `main` の文書が誤りになる。

### H5 — 「`bac_filter_node` は全方向指令を通さない」が偽である

`docs/nav2_integration.md`（日英）と `docker/nav2-jazzy/test_package.sh` のコメント。**`4739c6f`
（R16 M10対応）が持ち込んだ主張である。**

Jazzyコンテナ内で実ノードを `-p motion_model.type:=omni -p limits.vy_max:=0.3` で起動し、開けた
`/scan`・`/odom` と `cmd_vel_in(linear.x=0.30, linear.y=0.30)` を publish した実測:

```text
/cmd_vel_out : linear.x=0.23426  linear.y=0.18741  angular.z=0.00000
               (160 samples, max |linear.y| = 0.187409)
```

機構は `src/bac_filter_node.cpp` のCLEAR分岐 `applied = core_.limitReachableCommand(current, command)`
で、omniの `limitReachableCommand` が `vy` を保持し、capは `capSpeed` でベクトルに掛かるため
`cv != 0` なら `vy` は残る。非CLEAR分岐でもcoreの候補探索が `vy` を出す。**括弧書きの「純横指令は
出力0になる」だけが真で、主張本体が偽である。** 同じ偽の主張をinstall対象のdocker gateのコメントにも
書いている点が特に悪い。

## Medium

### M1 — 「非ホロノミック指令は影響を受けない」が差動二輪で偽

deadband再判定のコメントとR16対応資料。Params乱択16000 tick中**7 tick**で、0.567 / 0.800 m/sの差動
二輪指令が丸ごと `(0,0,0)`・status STOPになる（`c74fe7d` 単独に帰属）。Ackermannは曲率基準deadband
のため真に無影響である（6 seed × 16000行で0）。

### M2 — governorの弧補正2箇所が進行方向へ一般化されておらず、残項目にも無い

`evaluateProximity` のRELEASE-ONLY弧補正は `turn_radius = v/w`・中心 `(0, turn_radius)` を使うが、
holonomicの真の原点軌跡は中心 `(-vy/w, v/w)`・半径 `speed/|w|` である。同梱omni suiteでの発火は正面枝
147542回（うち `|vy| > 0.05` で116601回）、側方枝743009回（同373463回）。正面枝の解放は
`hazard = 1.0f`＝cap完全解放である。RELEASE-ONLYなので停止不能にはならないが、H1と同構図の1階層深い
残りである。

### M3 — governor一般化が指令速度の大振幅振動を増やす

`|Δ指令speed| > 0.5 * v_max` のtick数（seed 424242、holonomic）: `a9c6c31` 40 → `c74fe7d` 35 →
`68a8ed9`/head **427**。`side_gap` を前進軸へ戻すと23、H1を直すと68。対称footprintでも105対39（2.7倍）
である。governorが測定進行方向というフィードバック量に依存するようになった一方で、減衰も履歴も無い。

### M4 — 「閉じられなかったもの」の記録が不完全で、未申告の生存変異が多数ある

`SweptFrame::lead` **895**、governorの `travel_half` **473**（H1の対象。R16対応は「4要素中3件が生存」と

## main統合についての判断

**統合してはならない。** 統合前に満たすべき条件は次の5件である。

1. **H1** — governorの横方向スラブを非対称な `[-support(-n), support(n)]` へ直す。`arc_trajectory_evaluator`
   が既に `perp_left` / `perp_right` として持っている性質を、governorへ持ち込んでいない。同梱設定が
   対称footprintであるため、追加した対称性検査ではこの欠陥を検出できない。**非対称footprintでの検査が
   必要である。**
2. **H2** — deadband再判定が作る恒久停止を除去する。`min_eval_distance` の距離床がcreep域のヨーを
   過大に外挿していることが原因であり、救済策が生の `(0,0,0)` を返していることが吸収状態を作る。
   併せて**コストを測る**こと。
3. **H3** — 第1掃引のSTOP不変条件に加算文を入れる（または当該assertionを削り、第2掃引が持つ旨を書く）。
4. **H4** — 廊下の進入オフセット境界を実測へ合わせる（日英文書と試験コメント）。
5. **H5** — `bac_filter_node` に関する主張を実測へ合わせる（日英文書とdocker gateのコメント）。

M6・M7・M8・M9・M10・M13は**文字列の訂正のみで統合前に済ませるべきである**（実測と食い違う記録が
`main` に入るため）。M11・M12・M14も同様に安価である。残るMediumとLow全件は次サイクルで足りる。
