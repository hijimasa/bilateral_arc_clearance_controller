## H1 — 同梱設定のガードがyamlに紐付いていない

**修正**。`shippedExampleParams()` が **`config/bac_controller_ackermann.yaml` を実際に読む**ように
した。手書きコピーは削除した。パス は CMake が
`BAC_ACKERMANN_CONFIG_PATH` として渡す（`${CMAKE_CURRENT_SOURCE_DIR}/config/...`）。

読み取りは最小限の `key: value` パーサで行い、YAMLライブラリには依存しない。当該ファイルは平坦な
パラメータブロックであり、回帰試験と、それが守る設定ファイルとの間にビルド依存を持ち込まないことが
目的だからである。**ファイルが読めない場合、必要なキーが欠けている場合、`motion_model.type` が
`ackermann` でない場合は、既定値へ黙って退避せず失敗する**（空振りを避けるため
`g_shipped_config_loaded` を別途アサートしている）。

**検証**。複製ではなく実ファイルを編集して確認した。

```text
weights.hysteresis: 0.3 → 0.6
  FAIL: the shipped Ackermann example reaches its goal rather than orbiting
        (closest 0.466099 m, travelled 10.526865 m)

weights.hysteresis の行を削除
  FAIL: the shipped configuration declares weights.hysteresis
  FAIL: every value the scenario needs was read from the shipped configuration
```

指摘中の `limits.v_max: 0.5 → 1.4` は修正後も通過する。これは意図した挙動である。同シナリオの世界では
速い車両でもgoalへ到達し、接触もクリアランス低下も起こさないため、落とす根拠が無い。H1の実体は
「試験が当のファイルを読んでいない」ことであり、そちらは解消している。

## M1 — 単一軌道に合わせた閾値

**修正**。指摘の摂動掃引を再実行し、閾値を軌道からではなく**帯**から決め直した。

`testClutterField` の `max_curvature_step < 0.45` は **削除した**。正常動作の帯が0.81に達する一方で
破壊時の値は0.509と0.833であり、両者を分離する値が存在しない。存在しない分離を閾値で装うより、
検査を置かない方が正しい。削除した箇所にはその理由をコメントとして残した。操舵の連続性は、堅牢で
あることを確認した狭路と同梱設定の走行で引き続き検査する。

`testSafetyStopReverseEscape` の `curvature_sign_changes` は **15 → 22** とした。自分でも帯を測定した。

| | 測定範囲 | 観測値 |
|---|---|---|
| 正常 | `v_max` 0.30–0.60 × plant `curvature_rate` 0.7–2.0 | 0, 6, 7, 8, 17 |
| 破壊（hysteresisをヨーレート差へ） | 同シナリオの `v_max` | 25, 26, 28, 30 |

22は両帯の**間**にあり、正常側の最大17に29%、破壊側の最小25に12%の余裕がある。測定した帯を
コメントに明記した。

閾値の削除・緩和後も、対象としていたミューテーションは死ぬことを確認した（下の検証結果を参照）。

## M2 — 速度governorの閉ループ被覆

**修正**。指摘の「現実的な形」のミューテーション
（`v_hi = std::min(params_.limits.v_max, current.v + window_dv)`）を再現し、11本すべてを通過すること、
かつ迂回世界のクリアランスが 0.359 → 0.182 へ半減することを確認した。

`min_clearance` のアサーションを欠いていた2シナリオに追加した。

- `testObstacleDetour`: `min_clearance > 0.25`（正常0.359、当該ミューテーション0.182）。
  「接触が無いこと」に含意されない旨をコメントに残した。
- `testShippedExampleConfiguration`: `min_clearance > 0.20`（正常0.293）。こちらはミューテーション
  killerではなく安全側の下限として置いている。

**検証**。現実的な形・最強形の双方が落ちるようになった。

```text
mutant x_realistic → FAIL: Ackermann detour keeps physical clearance (0.182466 m)
mutant x_strong    → FAIL: 迂回クリアランス / clutter未到達 / 同梱設定クリアランス
```

## L2 — 近似重複・構造的に保証済みのアサーション

**一部のみ対応**。`max_abs_lateral < 0.15` が `min_clearance > 0.25` にほぼ含意される点、
`final_pose.x < 0.01` が `travelled_distance` を言い換えている点、`stop_ticks > 0` が実質的に偽に
なりえない点は、いずれも指摘のとおりである。

ただし**削除していない**。これらは冗長ではあるが、失敗時にどの性質が壊れたかを名指しする診断価値が
あり（例えば「走行距離は小さいが最終位置が前方」と「その逆」は別の壊れ方である）、実行コストは
無視できる。R11・R12で問題になったのは冗長さではなく、**検査していないのに検査しているように読める
アサーション**（到達不能コード、空振り）であり、それらは本ラウンドでもL3で対処している。

`!commanded_reverse` が `limits.v_min = 0` で構造的に到達不能である点は、意図の文書化として残す。
`v_min` の意味が将来変われば最初に落ちるべき検査である。

## L3 — `LateralWindow` の空振り

**修正**。`AckermannRun` に `lateral_samples` を追加し、`testNarrowCorridorCentering` で
`lateral_samples > 0` を明示的にアサートした。centeringの2つの検査が初期値のまま通過する経路を、

## L4 — 停止tickをまたぐ `max_curvature_step`

これで当該指標が標準停止をまたいで計測されることはない。

走行中のゼロ曲率デッドバンドの扱いは、指摘が「正しく意図的」と評価したとおり変更していない。
