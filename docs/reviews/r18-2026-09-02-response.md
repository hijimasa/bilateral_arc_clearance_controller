## 本ラウンドで変えた手順

R18はH2で「直したと報告したが実際には触っていないファイルがある」を指摘した。**本ラウンドは、
文書の主張を直すたびに `git diff --name-only` で当該ファイルが実際に変更集合に入っていることを
確認した。** また、レビューアが報告した数値も含め、**本文書と製品コードに書くすべての数値を自分の手で
測り直した。** 再現しなかった1件（M7の「16000 tick中8行相違」）は、レビューアの値をそのまま採らず、
自分の測定条件と測定値に置き換えている。

**製品コードの挙動は `ba544e2` から変わっていない。** `src/bac_core.cpp` の差分はコメントのみで、
非コメント行の増減は0である（`git diff src/ | grep -v '^[-+]\s*//'` が空）。R18のコード面の対応は
すべて試験側に入っている。

## High

### H1 — 掃引の安全不変条件の自己参照を解消した

試験側に、評価器と一切コードを共有しない接触距離の計算 `independentContactDistance` を置いた。
車体frameでは静止障害物点は瞬間中心 `c = (-vy/w, v/w)` のまわりを角速度 `-w` で回るので、接触は
「点の方位が矩形の内側に入る最小の回転角」である。円は4本の辺の直線と高々8点で交わり、その間では
内外判定が一定なので、交点を並べて各区間の中点を1回試せば厳密に決まる（直進指令は矩形の平行移動なので
軸ごとの区間の共通部分で解く）。両掃引はこの値で不変条件を再判定する。

さらに、**直進指令だけを対象にした第3の掃引**を追加した。既存2掃引はヨー規範が常に働くため直進tickを
ほとんど含まず（実測：第1掃引0件、第2掃引106件）、評価器の直進枝——`lead` と左右の支持幅が接触を
決める枝——にどちらも到達していなかった。新掃引は `heading_gain = 0` で60000試行を回し、885件の
検査に達する。`front` より `width / 2` が大きくなりうる車体分布を引いているのは、直進枝の変異が
**過小評価**になる条件がそこにしかないためである。

変異での確認（いずれも `ctest` を通していた）:

| 変異 | 対応前 | 対応後 |
| --- | --- | --- |
| `body_hit = abs_offset < side_extent * 0.5f` | SURVIVED | KILLED（第1掃引1件・第3掃引5件） |
| `frame.lead = body.front` | SURVIVED | KILLED（第3掃引2件） |
| `perp_left` / `perp_right` の入替（R18 M13） | SURVIVED | KILLED（第3掃引2件） |

`frame.trail = -body.rear` は依然SURVIVEDである（M13へ残す）。

### H2 — install対象2ファイルの「same size」を実測へ直した

`config/bac_controller_omni.yaml:28`、`CHANGELOG.rst:21`、`docs/parameters.md:54`、
`docs/en/parameters.md:55` の4か所すべてを改めた。`grep -rn "same size\|同じ大きさ"` は
`docs/reviews/` を除いて0件になる。

候補数は同数ではない。同梱の全方向設定の値（`limits.v_max` 0.4、`limits.vy_max` 0.3、
`limits.w_max` 1.0、`v_samples` 5、`vy_samples` 15、`w_samples` 25）で現在速度
(0.20 m/s, 0.0 rad/s) から測ると **omni 96・差動二輪130** である。この対が出るのはこの状態だけで、
現在速度を0.00〜0.40 m/sで41点掃引すると差動二輪側は156（31点）・182（9点）にもなり、omniは常に96で
ある。R18 M5が求めた測定条件はこの形で明記した。

### H3 — deadband分岐のコメントを実測へ直し、一般化を撤回した

計装して同梱の全方向suiteを走らせた実測は **267件発火、うち `safe_speed_for(finalized) == 0` は171件**
（64%）である。残る96件には0.0015〜0.671 m/sの安全速度が存在する。したがって
「straightened arcには安全速度が存在しない」という一般化は**偽であり撤回した**。

減速案を採らない理由は書き換えた。**安全性の理由ではなく、選ばれた指令がすでに許容的である以上、
車体が満たす必要のない量子化のために減速するのが筋違いだから**である。`14 of 14` の記述は
`src/bac_core.cpp` から除いた。

### H4 — deadband不適用を判別する回帰を追加した

「判別する回帰は用意できなかった」は偽だった。旧挙動は deadband適用後の値か厳密な `(0,0,0)` しか
publishしないため、`0 < |output.w| < angvel_min` は**構造的に0**である。

`testDeadbandIsSkippedRatherThanBreakingAdmissibility` を追加した。`angvel_min` を0.05〜0.35 rad/sで
振った30000試行での実測:

| 実装 | 該当tick | 移動tick |
| --- | --- | --- |
| 現行（deadbandを適用しない） | **255** | 21087 |
| 停止させる（R17が捨てた案1） | 0 | 21087 |
| deadbandを常に適用（旧挙動） | 0 | 21342 |

閾値は120で、両側の帯（255 / 0 / 0）から取った。`db_brake`・`db_nobrake` の両変異がKILLEDになる。
後者は第2掃引の許容性検査でも7件の違反を出す。

### M2 — `travel_left` / `travel_right` の向きを直接固定した

鏡映検査は左右の入替を原理的に検出できない（入替自体が鏡映対称）。左crab（進行方向 +y）では
travel lineの左が -x すなわち**後方張り出し**、右が +x すなわち**前方張り出し**になる。front 0.70 /
rear -0.30 の車体では、車軸の0.70 m前方にある障害物は掃引箱の内側、0.70 m後方にあるものは外側である。

実測: 前方 **0.560000 m/s** / 後方 **0.567726 m/s**。入替変異では **0.600000**（= `v_max`）/
**0.561427** と逆転する。1350セルの格子（壁距離 × 障害物オフセット × 現在横速度）では413セルが変化し、
うち183セルは**速度が上がる**。

### M3・M4 — 鏡映検査にヨーを実際に入れ、コメントの数値を実測に合わせた

`heading_gain` を0から1.5にし、`cur_w` の次元（-0.4 / 0 / 0.4、鏡像側は符号反転）を加えた。
セル数は48→**144**、うちヨーが非0のセルは**129**である。空虚でないことを検査する assertion も
足した（閾値は格子の1/4）。

コメントの「186 of 4000、worst 0.3496」は、この検査が出す数値ではなかった。実測は
**8 / 144、worst 0.080000**（現行の worst は 3.0e-08）で、これに置き換えた。
