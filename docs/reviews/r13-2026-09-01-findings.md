## 対象と方法

最新コミット `3bd88cb`（シナリオ拡充）を最重点とする。レビューを一度も受けていないコードであり、
かつ閾値の数値を作者自身が選んでいるため、新規欠陥の可能性が最も高い。あわせてR12の対応が実際に

検証手段: plain CMake Release `ctest` 7/7、Debug + ASan/UBSan（`detect_leaks=1`）7/7、
`docker/nav2-jazzy/verify.sh` 8/8。`/tmp` 複製上でのミューテーション。環境変数でパラメータ化した
`test/ackermann_scenarios.cpp` 複製による摂動掃引。受理されるAckermann設定4000通り × 40 tick =
160 000 tickのfuzz。`BacFilterNode::tick` の仮想path合成の再現実装。

## 結論

機能自体は健全である。160 000 tickのfuzzと11本の閉ループシナリオを通じて、Ackermann modelから
その場旋回・旋回半径違反・不正な後退・NaNを1件も生成できなかった。R12の2件の修正はいずれも実体を
伴っており、例外安全のロールバックはthrowするallocatorで再現し、adapterの誤解決はJazzyコンテナで
**両方向**とも殺せることを確認した。新規4シナリオのうち `testNarrowCorridorCentering` と
`testSafetyStopHoldsPosition` は設計が堅牢で、あらゆる摂動に耐えた。

無条件Goを妨げるのは、**最新コミットが自身の検証価値を3点で過大に主張していること**であり、そのうち
1点はすでに出荷済みの修正を無効化する。R11・R12が扱ってきたのはまさにこの種の欠陥、すなわち
「利用者が踏む不具合」ではなく「packageが自身について提示するevidenceの欠陥」である。

## Medium

### M1 — 新規4閾値のうち2つは単一軌道に合わせたtripwireであり、無害な摂動で正常動作が閾値を超える

コミットメッセージは閾値が「観測された正常動作と観測された破壊動作を、**両側に余裕をもって**分離する」
と述べる。この主張は、アサーションが対象としていないパラメータの摂動に耐えない。

`testClutterField` の `max_curvature_step < 0.45`（基準0.347）。controllerは**未改変**のまま
plant・車両・horizonのみを掃引した結果:

| 摂動 | `max_curvature_step` | 結果 |
|---|---|---|
| 基準 | 0.347 | pass |
| plant `curvature_rate` 1.0→1.3 | 0.458 | **FAIL** |
| plant `curvature_rate` 1.0→2.0 | 0.465 | **FAIL** |
| `v_max` 0.4→0.35 | 0.625 | **FAIL** |
| `v_max` 0.4→0.5（同梱yamlの値） | 0.479 | **FAIL** |
| `footprint.width` 0.95→1.0 | 0.475 | **FAIL** |
| `sim_time` 2.5→3.0 | 0.500 | **FAIL** |
| `sim_time` 2.5→2.0 | 0.808 | **FAIL** |

14通り中9通りで落ちる。この指標は混沌とした軌道上の最大値であり、摂動に対して単調ですらない
（krate 0.9→1.3: 0.375, 0.347, 0.368, 0.371, 0.458）。コミットが挙げる「破壊時」の値は0.509と0.833、
正常動作の分布は0.808に達する。**この境界は正常と破壊を分離しておらず、この軌道を他の2軌道から
分離しているにすぎない。**

`testSafetyStopReverseEscape` の `curvature_sign_changes <= 15`（基準7、破壊時28）。
`config/bac_controller_ackermann.yaml` が配布する `v_max = 0.5` では、未改変のcontrollerが**17**を
出して落ちる。ここでも非単調である（0.40で7、0.45で6、0.50で17）。

対照的に `testNarrowCorridorCentering`（`mean_abs_lateral < 0.04`、基準0.016、破壊時0.059）と
`testSafetyStopHoldsPosition` は試したすべての摂動に耐えた。この2つは設計が良い。

### M2 — 閉ループ試験は速度governorを実際には被覆しておらず、コミットの主張は最強形のミューテーションでしか成立しない

コミットは、単体試験でしか殺せなかった3件のミューテーションが「閉ループでも落ちるようになった」と
述べる。(a) hysteresisをヨーレート差にする、(b) refinementを無効化する、の2件は主張どおり再現する。
(c) は、現実の回帰が取る形では再現しない。

- `v_hi = current.v + window_dv`（capを完全に外し `v_max` すら超えうる）: コミットの数値を再現し、
  clutterがx=3.78で2166 stop tickを出して停止する。**KILLED**。
- `v_hi = std::min(params_.limits.v_max, current.v + window_dv)`（**呼び出し側の**capのみ無視し
  `v_max` は守る = 近接governorの回帰が実際に取る形）: **11本すべて通過**。
  `BacAckermannMotionModelUnit` だけが捕捉する。

さらに悪いことに、この生き残るミューテーションは迂回世界のクリアランスを**半減**させる
（`min_clearance 0.358 → 0.182`）が、誰も気づかない。`testObstacleDetour` と
`testShippedExampleConfiguration` が、`min_clearance` のアサーションを持たない唯一の2シナリオだから
である。同梱設定シナリオも 0.293 → 0.252 へ落ちるが未検査である。

### L2 — 新規アサーションの一部が近似重複または構造的に保証済み

- `testSafetyStopHoldsPosition` の `stop_ticks > 0` は160 tick中160であり、`travelled_distance < 0.05`
  が既にある以上、実質的に偽になりえない。`final_pose.x < 0.01` も `travelled_distance` をほぼ
  言い換えている（`v_min = 0` ではxは単調非減少）。
- `!commanded_reverse` は `limits.v_min = 0` では構造的に到達不能である。
  `sampleCandidates` は `v_rev = max(v_min, …) = 0` を計算し、`v_rev < -1e-3` を満たさないため
  後退候補が存在しない。160 000 tickのfuzzでも不正な後退0件。
- `testSafetyStopHoldsPosition` の `!offered_in_place_rotation` は非弁別的である。同一世界を差動二輪
  参照設定で走らせても旋回せずその場保持する。`testSafetyStopReverseEscape` では弁別的である

- `testNarrowCorridorCentering` の `max_abs_lateral < 0.15` は `min_clearance > 0.25` にほぼ含意される。

### L3 — `LateralWindow` の集計は窓に一度も入らない場合に空振りし、間接的にしか守られていない

`lateral_samples == 0` のとき `mean_abs_lateral` と `max_abs_lateral` は初期値 `0.0f` のままとなり、
centeringの2つのアサーションは通過し、失敗メッセージは "mean |y| 0.000000" と表示される。現状は
同一テスト内の `expect(run.final_pose.x > 11.0f)` が担保しているが、結合が暗黙的である。

### L4 — `max_curvature_step` が停止tickをまたいで計算され、`stop_ticks < 20` と相互作用する

コメントは「largest per-tick commanded curvature jump」と述べるが、`had_previous_curvature` と
`previous_curvature` は `|command.v| > 1e-4` のtickでしか更新されない。`testClutterField` が許容する
19 tickの停止をまたぐと、「per-tick」のstepが約1秒ぶんの操舵変化を表すことになる。
`curvature_sign_changes` にも同じスキップが効く。ただし走行中のゼロ曲率デッドバンドの扱い自体は
正しく意図的である（左折→長い直進→右折を1回と数えるのは「振動」の意味論として妥当）。

`travelled_distance` と `stop_ticks` の `!path.empty()` ガードはいずれも正しい。`gotoPointPath` は
`goal_tolerance = 0.3 m` 以内で空pathを返すため、到達後の停止tickは正しく除外される。ガードが無ければ
`testNarrowCorridorCentering` の `stop_ticks == 0` は充足不能である（120秒シム、走破約30秒）。

### L6 — `AckermannMotionModel` のコンストラクタのコメントが過大主張になっている

R12 L1の修正は有限性と `limits.w_max` の検査を `validateMotionModelParams` にのみ追加した。

## 検証して問題を確認しなかった項目

- **R12 L1（パラメータ検証）は十分である**。ランダム生成した**受理される**Ackermann設定4000通り ×
  40 tick = **160 000 tick**。`turn_radius_min` 1e-3〜1e4、`w_max` 1e-3〜50、`w_refine_steps` ∈ [-2,6]、
  `v_samples` ∈ [-2,8]、`w_samples` ∈ [-2,30]、`sim_time` 1e-5まで、`control_period = 0`、`acc_w = 0`、
  `max_points ≤ 0`、`velocity_min` 2まで、空/短/後方/回転pathをランダムに与え、manoeuvre中の `reset()`
  も注入した結果、**NaN/inf出力0件、その場旋回0件、旋回半径違反0件、不正な後退0件、速度境界違反0件**。
  clampを崩せる他のパラメータは見つからなかった。
- **R12 L2（例外安全）は真にstrongである**。throwする `operator new` で検証した。`setParams` 失敗後も
  `operator=` 失敗後も `params()` とmodelは整合し、`limitReachableCommand((0.3,0),(0.3,0))` は
  `(0.3, 0.0)` を返し、objectは完全に再利用可能で、後方planに対する `process()` はspinではなく
  Ackermannの答え `(-0.2, 0.0)` を返す。`Params` はtrivially copyableであり `params_ = params` は
  throwしえないため、`try` ブロックは唯一の失敗点を覆っている。
- **R12 M2（adapter分離）は両方向を殺す**。Jazzyコンテナで、`"diff_drive" → ACKERMANN` は
  「the default Nav2 configuration is differential drive and turns on the spot」で落ち、
  `"ackermann" → DIFF_DRIVE` は「forward-only Ackermann brakes for a rear plan instead of yawing」で
  落ちる。いずれもexit 1、7/8。
- **`shippedExampleParams()` は現時点でyamlと一致する**。対応する22値すべて（耐久性の問題がH1）。
- **ミューテーション(f)は実際に生き残り、捕捉する世界を構成できなかった**。狭路・clutter・offset通路で
  `turn_radius_min` ∈ {1, 2, 3}、加えて `v_max = 0.2`（`yawRateBound(v_probe) ≪ 0.4` でclipが最大限
  効く条件）を試した。差は小数第3位で、どのアサーションも反転しない。作者の説明は経験的に支持される。
  ただし根拠の精緻化として、`turn_radius_min = 1.0` かつ `v_max ∈ {0.4, 0.5}` ではclipは構成上ほぼ
  no-opである（`min(0.4, |v|/R) = 0.4`）ため、「世界の性質」は正確には「この半径と速度の組み合わせの
  性質」である。もっとも大半径の世界でも捕捉できない。
- **R12 L5（clampされない仮想path）はAckermannでは良性である**。`BacFilterNode::tick` の合成を
  上流指令32通り × 障害物配置で厳密に再現した。合成される弧は確かに退化している（例: `(0.05, 0.6)` は
  半径0.25、3 mの弧で約1.9回転、path終端 `(-0.13, 0.04)`）が、Ackermannの答えは常に、自身の旋回円
  上限でのunder-steerした前進弧か、fail-safeな `(0,0)`/`STOP` のいずれかであり、後退もspinも生じない。
  同じ合成を**差動二輪**で行うとspinと、前進の上流指令に対する後退が生じるため、この退化は既存の
  差動二輪側の問題であって、Ackermann modelが持ち込んだものではない。
- **ビルドとsanitizer**。package自身の `-Wall -Wextra -Wpedantic` で警告0。
  `-Wconversion -Wfloat-equal -Wold-style-cast -Wdouble-promotion -Wshadow` では33件あるが、すべて
  様式上のもので大半はtestコードであり、新規ファイル中の3件は符号反転カウンタの意図的な `±1.0f`
  番兵比較とfloat→doubleの昇格1件である。ASan+UBSan Debug は `detect_leaks=1` で7/7 clean。
- **決定性**。`-O0`、`-O2`、`-O3 -march=native` で同一結果。`-ffast-math` ではclutterの
  `max_curvature_step` が0.417へ動く（M1参照）。
