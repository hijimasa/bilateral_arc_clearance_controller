## H1 — 同梱設定例が回帰試験に通らない

**修正**。指摘は再現した。`weights.hysteresis` のみを変えて実行すると、同梱設定例（0.6）で
`testGentleGoalTurn` と `testObstacleDetour` が落ち、8 mのgoalに対し 27.9 m / 34.6 m 走行して周回する。

対応方針として、**差動二輪の既定値 0.6 は変更しない**。この値は公開済みの正準216 episodeと公平条件比較
216 episodeを生成した前提であり、変更すればREADMEおよび
[method comparison](../method_comparison.md) が引用する数値がすべて無効になる。実測では
`Weights::hysteresis` を 0.3 / 0.45 へ下げても差動二輪17シナリオは通るが、通ることと、公開済みevidenceの
前提を動かさないことは別問題である。

したがってAckermann側に適正値を持たせた。

1. `config/bac_controller_ackermann.yaml` を `weights.hysteresis: 0.3` とし、差動二輪の既定値ではない
   こと、曲率差の罰則が速度とともに縮まないため 0.6 では経路追従を圧倒すること、この値が
   `bac_ackermann_scenarios` の実行値であることをコメントに明記した。
2. `Weights::hysteresis` の宣言コメントに、単位がモデルで異なるため値が**モデル間で転用できない**こと、
   既定値は差動二輪向けの調整値であること、Ackermannではより低い値が必要で同梱設定例を参照すべきことを
   記載した。
3. 試験fixtureの `params.weights.hysteresis = 0.3f` に、これが同梱yamlの値であること、`Weights` 既定値
   （0.6）では周回することをコメントで明示した。

**数値の一致だけでは弱い**ため、同梱設定を丸ごと走らせるシナリオ
`testShippedExampleConfiguration` を追加した。`shippedExampleParams()` は
`config/bac_controller_ackermann.yaml` の footprint・margin・limits・weights・`sim_time` を写し、
障害物迂回の世界で走らせて、周回せずgoalへ到達すること、接触が無いこと、その場旋回を使わないこと、
自身の旋回円を守ることを検査する。

**検証**。`shippedExampleParams()` の hysteresis を 0.6 に戻すと当該シナリオが落ちることを確認した。

```text
FAIL: the shipped Ackermann example reaches its goal rather than orbiting
      (closest 0.466099 m, travelled 10.526865 m)
```

## M2 — 差動二輪のNav2 adapter coverage

**修正**。指摘のミューテーション（`"diff_drive"` が `MotionModelType::ACKERMANN` を選ぶ）が検証一式を
通過することを再現した。

`testControllerAdapter` の fixture を**既定設定（差動二輪）へ戻した**。ライフサイクル、TFエラー、
scan fallback、速度制限、diagnosticsは、既存利用者全員が動かす設定の下で実行される状態に復帰した。
その上で、後方planに対し差動二輪が**その場旋回する**ことを積極的に検査するアサーションを置いた。

Ackermannのパラメータ配線は、独立したライフサイクルノードとcostmapノード上で動く
`testAckermannAdapterConfiguration` へ分離した（costmapノード名は `NodeOptions::arguments` で
`ackermann_costmap` へ変更し、既定設定側と干渉しないようにした）。同じ後方planに対しAckermannが
`(0, 0)` へ制動することを検査する。

2つのテストが同一tickの表と裏を検査するため、`motion_model.type` がどちらへ誤解決しても必ず一方が落ちる。

**検証**。同じミューテーションを再適用し、Jazzyコンテナで落ちることを確認した。

```text
FAIL: the default Nav2 configuration is differential drive and turns on the spot
```

R12が「Ackermann側のアサーションは空振りではない」と確認した点はそのまま維持している。
冗長だった2つの `rear_command` アサーション（L3）も、この再構成で各テスト1件ずつに整理された。

## L1 — 負の `limits.w_max`

**修正**。`validateMotionModelParams` のAckermann分岐で `limits.w_max` も検査し、あわせて
`turn_radius_min` と `w_max` の有限性（`std::isfinite`）も要求するようにした。曲率上限は
`min(w_max, |v| / turn_radius_min)` であり、いずれかが非正または非有限であれば上限が負または無限大に
なるため、両方を同じ不変条件として扱う。コンストラクタのコメントが主張していた内容が、これで実際に
成立する。

## L2 — 例外安全の強度

**修正**。`setParams` と `BacCore::operator=` を、失敗時に `params_` を巻き戻す形へ変更した。

```cpp
const Params previous = params_;
params_ = params;
try { rebuildMotionModel(); }
catch (...) { params_ = previous; throw; }
```

生き残ったmodelは `params_` を参照で保持するため、巻き戻しによって「このobjectが報告する設定」と
「modelが読む設定」が常に一致する。`setParams` の hysteresis / alignment 状態のリセットは、
再構築が成功した後に `previous` と比較して行うよう順序を入れ替えた。コピーコンストラクタは元から
問題がない（失敗すればobjectごと破棄される）ため変更していない。

## L3 — テスト品質の残渣

**修正**。

- `max_curvature_step` に実際の検査を与えた。1制御周期（50 ms）で全舵角範囲
  （`2 / turn_radius_min`）の半分を超えて曲率を振らないことを、狭路シナリオと同梱設定シナリオで
  検査する。実測値は corridor 0.367、detour 0.75、shipped 0.375 1/m であり、閾値 1.0 1/m に対して
  余裕がある。
- `testDeadEndStopsWithoutRotating` に `!violated_turning_radius` を追加した。
- 冗長な `rear_command` アサーションはM2の再構成で解消した。
- 差動二輪の `isCommandKinematicallyValid` に対する検査を
  `bac_diff_drive_motion_model_unit::testTranslatingTurnRadiusGuard` として追加した。前進・後退とも
  `turn_radius_min` より鋭い弧を拒否し、より緩い弧を受理し、その場旋回は対象外であることを検査する。
  これはR11のM1文書訂正1で明示的に文書化した挙動であり、これまで未検査だった。
  **当該述語を常にtrueへ改変すると落ちることを確認済み**である。

## L5 — filter nodeの仮想path

**未対応。残項目とする**。R12自身がSUSPECT扱いとし、誤出力を生むシナリオを構成できていない。
CLEAR pass-throughでは `limitReachableCommand` が補正するため、影響が疑われるのはAVOIDING中に
上流指令が車両の旋回円より鋭い場合に限られ、想定される帰結は良性のunder-steerである。
仮想path合成側で `turn_radius_min` へclampするのが素直な対応だが、挙動変更を伴うため、
再現シナリオを作ってから着手する。
